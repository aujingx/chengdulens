# Chengdu Lens：Agent 体验评测 Case 集

## 目的与证据边界

本文定义当前 Demo 的人工体验评测集，用于验证受控知识、约束优先、证据表达与降级行为。

- **已实现**：结构化旅行者画像、收藏/拒绝/路线/天气本地状态、受控的 8 个地点、雨天局部重规划和流式 AI 对话。
- **当前对话边界**：模型通过系统 Prompt 接收受控地点资料与用户上下文；这不是生产级工具运行时或独立约束引擎。
- **不构成生产指标**：每个 Case 需要人工运行和复核；未执行的 Case 不得被表述为通过率。

## 评测原则

1. 硬约束优先于匹配度。
2. 证据优先于流畅但无依据的表达。
3. 信息缺失或冲突时，提出一个高价值澄清问题，而不是猜测。
4. 重规划时不能静默删除已确认选择。
5. 未经确认的推断偏好不能写入长期用户记忆。

## 执行记录

每条 Case 记录执行日期、Demo 版本、语言、当前画像、输入、输出、Pass / Fail、严重级别和归因。

- **P0**：虚构事实、忽视硬约束、作出无依据的服务承诺，或静默删除已确认选择。
- **P1**：应澄清而未澄清、遗漏关键风险，或推荐违反明确偏好的选项。
- **P2**：表达冗长、理由不清或产生不必要的对话轮次。

## 归因分类

| 归因 | 示例 | 优先处理方式 |
| --- | --- | --- |
| 受控知识缺口 | 缺少预约或英文服务资料 | 补充来源和更新时间；不让模型填补缺口 |
| 产品规则缺口 | 未定义时间不足时的决策 | 先补 Case 与验收标准，再决定是否自动化 |
| Prompt / 回应契约问题 | 未清楚表达“需确认” | 优化回应契约或示例 |
| Demo 范围限制 | 请求实时或库外信息 | 明确范围并提供诚实降级 |
